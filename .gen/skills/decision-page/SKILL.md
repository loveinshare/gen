# decision-page — 多轮对齐，关闭才放行

**决策不是登记表，是一场会。** 每个模糊点值得一张你写字、质问、反复修订的页面；工具读完你的批复必须**回应**，而不是标记"已读"。

---

## 一、触发与不触发

**触发（任一）**

| 条件 | 例子 |
|---|---|
| 存在 ≥2 个合理路径，且选择影响用户可感知行为 | 令牌存 cookie 还是 header |
| agent 发现自己在**猜**意图 | "用户说'快'，我按 200ms 假设了" |
| 隐藏假设会被写进代码但没人确认 | 时区按 UTC 存、金额用整数分 |
| key / 契约 / 架构 / 数据迁移变更 | 改打分算法的权重 |
| 不可逆或高代价 | 删字段、换存储、改对外 API |
| 用户主动要求 | "先给我看方案，别写代码" |

**不触发**

- 纯线性、无分支的单点确认（如"这个变量叫 a 还是 b"）→ 聊天里问一句即可
- 实现细节且有客观最优解（如"用 `map` 还是 `for`"）→ agent 自行决定，写进 `progress.md`
- 已经在 `thread.md` 有结论且未被推翻的旧问题（禁止重复开页）

**降级通道（必须有，否则决策会变成拖延）**：若某项**无法获得用户输入**（用户不在、信息不足），工具可提议"按默认行为 X 执行，风险记入 `ambiguities.md`"，但**必须用户明确说"就按默认走"**才生效，且页面标 `blocked→waived`，不得静默。

## 二、目录与文件

```
.gen/decisions/D-YYYYMMDDHH-<slug>/
├── page.html          # 最新交互页（唯一入口）
├── thread.md          # 权威多轮线程，append-only
├── response-r1.md     # 第 1 轮用户批复（原文）
├── response-r2.md
└── page-r1.html       # 历史轮快照（归档，不再改）
```

| 文件 | 谁写 | 权威性 |
|---|---|---|
| `thread.md` | agent（append） | **权威记录**。冲突时以它为准 |
| `page.html` | agent 生成 | 最新界面；只反映当前轮 |
| `response-rN.md` | 用户（工具可代落盘，内容不改） | 用户原话 |
| `page-rN.html` | agent 归档 | 冻结 |

**ID**：`D-<TS>-<slug>`，与目录名一致，永不复用（见 `.gen/AGENTS.md` §3.3）。

## 三、交互页技术要求（硬性）

1. **单文件**：内联 CSS/JS，UTF-8，`<html lang="zh-CN">`，**零网络请求**（离线可开，file:// 可开）。
2. **首屏不出现代码**：代码/日志折叠在 `<details>` 二级。
3. **顶部固定状态条**：要达成什么 · 你在决定什么 · 第几轮 · 未关闭项数 · 本轮新增项数。
4. **每项一个决策控件**，必须含：
   - 问题（一句）与**为什么现在必须定**
   - 选项表：`做法 / 收益 / 代价 / 可逆性`
   - **推荐项 + 理由**（推荐但不预选）
   - **待确认假设**：agent 替你假设了什么（独立小节，高亮）
   - **已排除项 + 排除理由**（防止你重复提被否掉的方案）
   - **若不决策的默认行为**：你什么都不说，我会怎么做（让沉默有代价，但**不等于同意**）
   - **文字输入区**：批注 / 反问 / 要求解释 / 改写方案，`textarea` 不限字数
   - 状态标记：`未回答` / `已批注` / `已关闭`
5. **无任何预选**。空 = 未回答，**绝不等于同意**。
6. **已关闭项折叠**，仍开放项与新增项展开；保留本项的历史批复供追溯。
7. **底部导出区**：把所有输入拼成结构化 Markdown，提供两个按钮——`下载 response-rN.md`（Blob + `a[download]`）与 `复制到剪贴板`（`navigator.clipboard` 失败时降级为选中 textarea 文本）。**file:// 下剪贴板可能被拒**，所以必须同时给出"手动全选复制"的可见 textarea。
8. **移动端可用**：`<meta name="viewport">`，单列布局，输入框足够大。
9. **可打印**：`@media print` 隐藏按钮、展开折叠。

> 参考实现思路：`visual-plan` 的决策控件 + lock 机制、`visual-review-page` 的逐项批注与轮次快照。本体系的增量是**多轮由工具主动驱动**且**关闭是硬闸门**。模板见 `templates/decision/page.html`。
>
> **写盘通道（推荐）**：`node .gen/scripts/gen.mjs serve --decision <id>` 会以 `http://127.0.0.1:7070` 提供页面，页面检测到 http 协议后启用「保存到 .gen/」按钮，点击即由服务端写入 `response-rN.md`，免去复制粘贴。只绑定本机回环地址，只允许写该决策目录下的 `response-rN.md`。

## 四、多轮流程（逐步执行，不许跳）

### Round 1 — 工具发起

1. `date +%Y%m%d%H` 取时间戳，建目录 `decisions/D-<TS>-<slug>/`。
2. 写 `thread.md` 的 Round 1：`### agent` 下写问题陈述、选项、推荐、假设、默认行为。**此时"用户批复"与"agent 回应"留空占位。**
3. 按模板生成 `page.html`（填充数据，不要留 `TODO`）。
4. 更新 `decisions/INDEX.md` 新增一行：状态 `open`、轮次 `1`、未关闭项数。
5. 告诉用户：路径（可点击打开）、**一句话说明这次要定什么**、以及"你可以直接在每个框里写字，然后点导出，把结果贴回来"。

### 用户批复

6. 用户打开页面逐项输入 → 导出 → 把 Markdown 贴回聊天（或存为 `response-r1.md` 并告知）。
7. **工具必须把批复原样落盘**为 `response-rN.md`（不改措辞、不"总结"、不删口语）。

### 工具回应（这一节是核心，最容易偷懒）

8. 逐项处理，**每项都要有可见回应**：

| 用户说了什么 | 工具必须做什么 |
|---|---|
| 提问 / 要求解释 | 解释，并**修订页面里的说明文字**（不是只在聊天里答） |
| 反问 / 质疑依据 | 给依据（文件、数据、命令），依据不足就承认并改方案 |
| 直接否定某方案 | 移入"已排除项"并写排除理由，**本轮起不再推荐** |
| 改写方案 | 复述你的理解（一句话），确认没歪，再更新选项 |
| 新担忧 | 判断是否上升为新决策项（默认：是，进"本轮新增"） |
| 说"这项定了" / "按推荐" | 该项标 `closed`，thread 记**依据原话** |
| 没提到某项 | 保持 `unanswered`，并在回应里**明确点名**："第 3 项你没提，我先保持开放，因为……" |

9. **禁止**只说"已更新""已按您的意见修改""好的"。必须能让人看出：你听懂了什么、改了什么、还有什么没解决。
10. **每轮最多新增 3 个问题**。超过说明拆得不够细（拆成新决策目录），否则会发散成无底洞。
11. 追加 `thread.md`：`## Round N` → `### agent（发起/回应）`、`### 用户批复`（原文引用）、`### agent 回应`（逐项）。
12. 归档旧页 `page-r(N-1).html`，生成新 `page.html`（第 N 轮，顶部状态条更新，已关闭折叠、新增项高亮）。
13. 更新 `INDEX.md` 的轮次与未关闭项数。
14. 回复用户：**逐项摘要 + 未关闭清单 + 新问题**，并给出页面路径。

### 关闭

15. 所有项 `closed`，且 thread 有最终结论段，才可关闭：
    - `thread.md` 写 `## 最终结论`：每项定了什么、理由（引用用户原话或依据）、影响范围、需同步的文件（spec / 架构 / key / 测试）
    - `INDEX.md` 状态改 `resolved`，记关闭时间
    - 若涉及架构或 key：写 `architecture/agent/adr/<TS>-<slug>.md`，**只写摘要并链到 thread.md**，不复制正文
    - 同步更新 `specs/<feature>/decisions.md`（只列 ID + 一句结论）
    - `progress.md` 追加一行
16. 关闭后**才可以**进入 `implement`。

## 五、关闭判定（不许单方面宣布）

- 单条 `closed` 的条件：用户在批复中**明确表态**（"这项定了""按 B 走""同意推荐"），且 thread 记录依据原话。
- 整个决策 `resolved` 的条件：所有项 `closed` + 最终结论段已写 + `INDEX.md` 已更新。
- 用户说"你决定吧"→ 记 `waived`，写明"由 agent 决定"及理由，仍算关闭，但**风险写入 `ambiguities.md`**。
- 用户沉默 / 没提到 → 该项保持 `unanswered`（决策整体仍为 `open`）。
- 用户明确说"先不做这个"→ `status: blocked`，写明阻塞原因与解锁条件。

## 五之二、让用户看见"这轮改了什么"

每轮生成新页面后，把上一版另存为 `page-rN.html`，然后：

```bash
node .gen/scripts/gen.mjs decision-diff --decision <D-id>
```

产出 `diff-r{from}-r{to}.html`：按决策项分组、左旧右新，标出新增/删除的选项、被改的代价与推荐。
**这是"逐项回应"的可验证证据**——用户不用重读整页，就能确认你真的按他的话改了。
若上一步没保存 `page-rN.html`，命令会报错并提示命名，不会静默跳过。

## 六、闸门（`implement` 会执行）

```text
读 .gen/decisions/INDEX.md
→ 过滤出与当前 feature/slice 相关的决策
   （优先 links 命中 S-<feature>-NN 或 feature 字段一致；
     无 links 时按 slug/标题人工判断并在回复中说明匹配依据）
→ 若存在 status ∈ {open, blocked}：
    拒绝执行，输出：
    "以下决策未关闭，不能进入实现：
     - D-2026081502-token-store（open，未关闭项：2）
       未关闭项：Q1 令牌存储位置 / Q3 跨域策略
     请先在 decisions/D-.../page.html 批复，或说明按默认行为执行。"
→ 全部 resolved 或 waived 才继续（waived = 用户授权按默认行为执行，风险已入 ambiguities.md）
```

**闸门范围最小化**：只拦"与当前切片相关"的决策，不拦全项目所有决策；匹配依据必须写在回复里，避免误伤。

## 七、页面模板字段（生成时必须填满）

```yaml
title: 令牌存储方案取舍              # 一句话
round: 2
goal: 让登录态在移动端和 Web 都能用，且可主动失效
decision_question: 令牌存在哪里
items:
  - id: Q1
    question: 令牌存 cookie 还是 Authorization header？
    why_now: 这决定 CSRF 防护、跨域配置和后续所有接口改造
    options: [...]
    recommend: B
    assumptions: ["假设你有独立前端域名，若同域则 A 更简单"]
    excluded: [{option: C, reason: 需要引入额外网关}]
    default_if_silent: 按 B 实现，并在 README 记录风险
    state: unanswered    # unanswered | annotated | closed（不要写 open）
```

## 八、交付判定

一轮结束时逐条核对（缺则不算完成）：

- [ ] 每项都有**可见回应**：解释了、回答了、修订了、点名了没被提到的项（§四.8）
- [ ] 批复**原文**落盘为 `response-rN.md`，未被润色
- [ ] `thread.md` 追加了本轮：Round N → agent → 用户批复 → agent 回应
- [ ] `INDEX.md` 的状态、轮次、未关闭项数已更新
- [ ] 旧页已归档为 `page-rN.html`，新 `page.html` 顶部状态条正确
- [ ] 本轮新增问题 ≤3 条；超了说明该拆新决策目录
- [ ] 关闭时：`thread.md` 有 `## 最终结论` 段、`INDEX.md` 状态为 `resolved`、涉及架构/key 时写了 ADR 与 `specs/<f>/decisions.md`
- [ ] `progress.md` 追加了一行

**关闭前最后一道**：`gen.mjs lint` 不得报 E32（"假关闭"：状态 resolved 但最终结论仍是占位）。

## 九、反模式

- 页面里出现"以下为 AI 建议，请确认"却**没有具体选项和代价**（等于把决策踢回给人）
- 把 10 个问题塞进一页（人只会关掉）
- 一轮里声称"全部已关闭"但用户只说了"差不多"
- 页面读不出"当前第几轮、还剩几项"（用户无法判断进度）
- 批复原文被"润色"后落盘（追溯时失真）
- 依赖浏览器持久化（`localStorage` 在原页面里不可靠、换机就丢）——**导出文本才是持久化**
