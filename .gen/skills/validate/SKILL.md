# validate — 一条标准一条证据

**`unknown` 是合法结论，`pass` 不是猜出来的。**

## 触发

- 切片实现完成，准备收尾 / 汇报 / 合并
- 用户问"验过了吗""能上线吗"
- 阶段收束前

**不触发**：仅静态检查就够的 L1 微改（但要有 lint/类型检查记录）。

---

## 步骤

1. **取标准**：从 `spec.md` 抄出本切片对应的验收标准（AC 编号），**不新增、不改写**。若标准本身不可判定，回到 `analyze` 修标准，不要在现场"灵活解释"。
2. **设计验证方式**：每条至少选一种
   | 类型 | 适用 | 证据形式 |
   |---|---|---|
   | 自动化测试 | 逻辑/边界/回归 | 测试名 + 命令 + 结果行 |
   | 手动操作 | UI/交互/难以自动化 | 操作步骤 + 截图/输出 |
   | 接口探测 | API/契约 | `curl` 命令 + 状态码 + 关键字段 |
   | 数据核对 | 迁移/一致性 | SQL/脚本 + 前后对比数字 |
   | 静态证明 | 类型/权限/依赖 | 命令输出 |
3. **执行并记录**：命令原样写（可复制），输出只摘关键行（≤10 行），附时间。
4. **判定**：
   - `pass`：证据直接支持标准
   - `fail`：证据反驳标准 → **立即转 `repair`**，并写失败档案
   - `unknown`：没跑/环境不可用/标准不可测 → **写明原因**，不得写 pass
5. **写证据矩阵**到 `progress.md`（摘要）与切片/规格文件（完整）：

```markdown
| AC | 标准 | 验证方式 | 命令 / 操作 | 输出摘要 | 判定 | 时间 |
|---|---|---|---|---|---|---|
| AC-1 | 密码错误返回 401 且不含 token | 单测 | `pnpm vitest run tests/auth/login.spec.ts` | `2 passed (0.8s)` | pass | 2026111503 |
| AC-2 | 旧 token 在改密后 5 分钟内失效 | 手动 | 见下步骤 | 未执行：需要 Redis 实例 | unknown | 2026111503 |
```

6. **写测试台账**：每次执行都进 `tests/LEDGER.md`（一行），失败另建 `tests/failures/F-<TS>-<slug>.md`。
7. **收尾判定**：全 `pass` → `done`；有 `unknown` → `done-with-gaps`（在报告里显式列出未验证项与风险）；有 `fail` → `blocked`，转 `repair`。

## 交付判定

- [ ] 每条 AC 一行，无遗漏
- [ ] 每个 `pass` 都有命令与输出摘要（缺一视为未验证）
- [ ] `unknown` 都写了原因与补齐条件
- [ ] `tests/LEDGER.md` 已追加
- [ ] 没有用"整体跑通了"替代逐条证据

## 反模式

- 测试全绿就宣布所有 AC 通过（可能有些 AC 根本没测）
- 把别人/CI 的历史结果当本次证据（要标来源与时间）
- 为了凑 pass 而降低标准（改标准必须回 `analyze` 并记录）
- 环境起不来就写 pass（必须 `unknown` + 阻塞原因）
