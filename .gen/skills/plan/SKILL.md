# plan — 切片，不是甘特图

**一片 = 一个会话内能做完、能验证、能回滚的最小完整改动。**

## 触发

- `analyze` 已产出验收标准
- 用户说"给个计划""拆一下""先做哪部分"
- 现有计划失效（需求变了、发现新约束）

**不触发**：单片微改（L1）；紧急线上修复（先 `repair` 止血，事后补计划）。

## 步骤

1. **读输入**：`spec.md` 的验收标准 + 约束 + 风险；`ambiguities.md` 里影响排期的项；`decisions/INDEX.md` 的 `open` 项（它们会变成切片的前置）。
2. **定切片粒度**（硬约束）：
   - 单切片预期改动 ≤ 8 个文件、≤ 400 行 diff
   - 必须能独立验证（有自己的验收子集）
   - 必须能独立回滚（不依赖后续切片）
   - 超过 → 继续拆；拆不动 → 说明是 L3，先开决策
3. **排依赖**：画有向图（文本即可），标出哪些切片可并行、哪些有硬前置（迁移 → 代码 → 开关 → 清理）。
4. **每片写 5 件事**：

```markdown
### S-<feature>-01 <一句话目标>
- 验收：AC-2, AC-3（来自 spec，不新造）
- touch：`src/auth/*.ts`, `migrations/003.sql`（超出即停，需改计划）
- 做法要点：<3 行以内，不写实现细节>
- 回滚：`git revert <sha>` / 关掉 `FEATURE_X` 开关 / 反向迁移脚本路径
- 停止规则：若 <信号> 出现，停止并转 repair/决策，不带病继续
```

5. **写停止修复规则**（整份计划级别）：
   - 同一失败连续 2 次修复无效 → 停止，回 `analyze` 补证据
   - 发现需要改契约 → 停止，开 `decision-page`
   - 测试环境不可用 → 停止，标 `blocked`，不用"手工目测通过"替代
6. **标出决策前置**：哪些切片必须等某个 `D-...` 关闭才能开始；写进切片头部 `blocked_by: D-...`。
7. **落盘**：`workflow/plans/<TS>-<phase>.md`；同步 `specs/<feature>/plan.md` 指向它；`current-phase.md` 更新当前切片。
8. **计划修订**：不覆盖旧计划。实质调整 → 新计划文件 + `progress.md` 记"因何修订"。小调整就地改并在文件尾 `## 修订` 追加一行。

## 产物

`workflow/plans/<TS>-<phase>.md`，含：目标、非目标、切片表、依赖图、停止规则、决策前置、里程碑。

## 交付判定

- [ ] 每个切片都有验收 / touch / 回滚 / 停止规则四件套
- [ ] 切片数 ≤ 7（超过说明没拆干净或该分阶段）
- [ ] 明确写了"不做什么"（非目标），否则范围一定膨胀
- [ ] 决策前置已列，且没有切片依赖未关闭的决策
- [ ] 没有把实现细节写死（计划不是代码）

## 反模式

- 按"前端/后端/测试"横切（无法独立验证）
- 每个切片都"依赖前一片完成后才知道行不行"（滚雪球）
- 计划里写"预计工时"却没有任何验收点
- 把决策项留到实现时才想（违反闸门）
