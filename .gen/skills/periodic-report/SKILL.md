# periodic-report — 一页纸说清进展

**报告不是日记，是决策辅助。** 读完应该能回答：进展如何、卡在哪、要我做什么决定。

## 触发与不触发

**触发**

| 条件 | 例子 |
|---|---|
| 阶段收束 / 里程碑达成 | 鉴权重构这一片做完 |
| 固定节奏（建议每周五） | 第 46 周进展 |
| 线上事故 / 数据问题 | 登录 500 复盘 |
| 发版前 | v1.4.0 发版说明 |
| 用户说"出个报告""总结一下" | — |

**不触发**

- 本周期无实质变更 → 在 `reports/INDEX.md` 记一行"无变更"，**不生成文件**（宁缺毋滥）
- 只是想看当前状态 → 用 `gen.mjs status`，不必写报告
- 报告里要问的问题 → 走 `decision-page` 决策页，别在报告里问（报告是只读的）

## 一、节奏（避免仪式化）

| 类型 | 触发 | 必需 | 命名示例 |
|---|---|---|---|
| `phase` 阶段报告 | 阶段收束 / 里程碑达成 | 是 | `2026111502-鉴权重构阶段评审.html` |
| `weekly` 周报 | 每周固定（建议周五） | 有实质变更才写 | `2026111502-第46周进展.md` |
| `incident` 事故报告 | 线上故障 / 数据问题 | 是，24h 内 | `2026111502-登录故障复盘.html` |
| `release` 发版说明 | 发版前 | L2+ 必写 | `2026111502-v1.4.0发版.md` |

**不写的情况**：本周无实质变更 → 在 `reports/INDEX.md` 记一行"无变更"，不生成文件。宁缺毋滥。

## 二、命名与格式

> 初稿可以机械生成：`node .gen/scripts/gen.mjs report --title "<标题>" --write`
> 它只会算数字（决策/测试/失败/进度），结论与判断仍必须人写，且 `status` 保持 `draft` 直到核对完。

- 路径：`.gen/reports/YYYYMMDDHH-<标题>.md|.html`
- 标题允许中文，≤20 字，不含空格与 `/ \ : * ? " < > |`
- **格式判定**（遵守根 `AGENTS.md` §4）：
  - 有 ≥3 项并排对比、需要图表、需要分区导航、需要交互 → **html**
  - 纯线性小结、单页能扫完 → **md**
  - 选 html 时首行写 `<!-- 为何 html：<判据> -->`
- 阶段报告与事故报告**建议 html**（信息密度高，需要看板）。

## 三、固定结构（十节，可合并但不可缺）

1. **一句话结论**（≤40 字，说人话）
2. **本周期做了什么**：3–7 条，每条带证据链接（`S-...` / 提交 / 决策 ID / 测试 ID）
3. **数字看板**：切片 完成/总数、决策 关闭/开放、测试 通过率、失败 未结/已结、改动 文件数/行数
4. **决策与变更**：新增/关闭的决策，**已实施但未走决策的**（重点标红）
5. **风险与阻塞**：每条写"影响 / 触发条件 / 我建议怎么办"
6. **质量**：测试覆盖了哪些 AC、哪些 `unknown`、flaky 情况
7. **架构影响**：哪个模块/契约/key 变了，链 `arch-sync` 产物
8. **下一步**：3 条以内，每条可验收
9. **需要你拍板的事**：0–3 条，每条给"不决定的后果"
10. **附录**：命令、日志路径、环境矩阵引用

## 四、写法规范（反晦涩）

- 每节首句是**结论**，不是背景。
- 数字必须来自文件（台账/看板），不凭记忆；写不出处就写 `未统计`。
- 不用"基本完成""差不多""应该没问题"；用 `3/5 完成，2 项 blocked`。
- 术语首次出现给一句解释，或链 `architecture/human/GLOSSARY.md`。
- 段落 ≤4 行，每节 ≤5 段；超过就拆小节。
- **不复制**其他文档正文，只链接（R2）。

## 五、落盘与索引

1. 写文件到 `reports/`。
2. `reports/INDEX.md` 顶部插入一行（倒序）：`| <TS> | <标题> | <类型> | <一句话结论> |`。
3. 交叉更新：`current-phase.md` 记"上次报告：<文件>"；若报告暴露新疑问 → `ambiguities.md`；若需要拍板 → 开 `decision-page` 而不是在报告里问（报告是只读的）。
4. 季度归档：移入 `reports/archive/YYYY-QN/`，`INDEX.md` 保留指针。
5. `final` 后只许追加 `## 勘误` 节。

## 六、HTML 报告的硬要求

- 单文件、内联样式、无外链 CDN、`lang="zh-CN"`、可打印
- 顶部：标题、时间、周期、一句话结论、状态徽章
- 有目录锚点（节数 >6 时）
- 数字看板用表格或简单条形（纯 CSS，不引图表库）
- 移动端单列可读
- 首行 `<!-- generated by periodic-report @ <TS> from <sources> -->`

## 交付判定

- [ ] 十节齐（缺则写明"不适用 + 原因"）
- [ ] 每个数字能追到源文件
- [ ] 有"需要你拍板的事"，或明确写"本周期无需拍板"
- [ ] `INDEX.md` 已更新
- [ ] 格式判定理由已写（若选 html）

## 反模式

- 流水账（"周一做了什么、周二做了什么"）
- 只报好消息，`unknown` 和失败藏在附录
- 报告里提出新决策却不建决策页（用户看不到闸门）
- 双份 md+html 各自维护（必然漂移）
